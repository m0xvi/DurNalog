# Турналог — передача редизайна разработчику

Документ для человека, который будет переносить макет в существующее приложение  
**Python + customtkinter + ttk.Treeview + PyInstaller**.

Если времени мало — прочитайте блоки **0, 1, 2, 6**. Остальное — по ходу работы.

---

## 0. За 30 секунд

Это **редизайн GUI**, не новое приложение и не веб-версия.

- Стек, расчёт налога, pandas, openpyxl, sqlite, сборка `dist\TurNalog` — **не трогать**.
- Тема — **только светлая**.
- HTML — **макет**, не код. Переписывать на tkinter, пиксель-в-пиксель не требуется.
- Часть экранов в макете **выдумана** (карточки «налог за квартал», поиск, тосты, сегмент квартала). Их нельзя слепо кодировать — сначала сверить с текущим `gui.py` и с заказчиком. Список — раздел 2.

Цель: бухгалтер с первого взгляда видит отель, файлы, квартал и одну зелёную кнопку. Настройки не пугают формулами.

## 3. Что нельзя менять (заморожено)

Логика:

- расчёт налога, формулы, плейсхолдеры `{P}{N}{R}{M}{T}{min}{rate}{div}`;
- «налог в цене» → делитель `100+ставка`;
- автопорог `минимум × (100+ставка) / ставка`;
- налог от стоимости без комиссии;
- комиссии агентов по периодам, синонимы;
- разбивка Чайковского по корпусам (листы 1&2, 1, 2, «нет корпуса»);
- дубли по истории, переход квартала **фиолетовым** в Excel;
- sqlite: история, дубли, пользователи; смена пути **без перезапуска**;
- роли: админ видит всё, пользователь отеля — только свой отель и его историю;
- `tkinter.filedialog` и `messagebox` для файлов / ошибок / подтверждений;
- сборка PyInstaller, папка `dist\TurNalog`.

Стек виджетов:

- окна, карточки, кнопки, поля, чекбоксы — **customtkinter** (`CTk`, `CTkToplevel`, `CTkFrame`, `CTkButton`, `CTkEntry`, `CTkCheckBox`, `CTkScrollableFrame`, `CTkLabel`);
- таблицы — **ttk.Treeview** (История, Пользователи);
- не переписывать GUI на Qt / web / Flet / custom widgets с HTML.

Тема: светлая, фиксированно. `set_appearance_mode("light")`. Тёмную не добавлять.

## 4. Принципы (чтобы не «улучшать» мимо)

1. Один главный экран = обработка **текущего** отеля.
2. Файл — объект с именем, не голая строка пути.
3. Параметры, которые бухгалтер задаёт каждый раз (квартал — **если** он ручной), должны быть на шаге 2, не внутри кнопки.
4. Формулы Excel — для 2% пользователей, по умолчанию скрыты.
5. Цвет отеля один и тот же в сайдбаре и в истории.
6. Если customtkinter не умеет (пунктир, стекло, градиент контента) — упростить, не тащить Canvas на каждый чих.

## 6. Экраны: что строить

### 6.1. Главное окно

```
[ системный titlebar Windows ]
[ сайдбар navy | контент             ]
[ статусбар: точка · текст · путь БД ]
```

**Сайдбар** (`fg_color=#1B2A4A`):

- Бренд: «ТУРНАЛОГ» + «налог по выгрузкам отелей».
- Группа «ОТЕЛИ»: три кнопки. Активная — `sidebar_act`, текст белый. Цветная точка 8 px слева.
- Разделитель.
- «История», «Настройки».
- Низ: кружок с инициалом, логин, роль, версия.

Права: если роль «отель» — в сайдбаре **только его отель** + История (своя) + без Настроек (или Настройки без чужих отелей / пользователей / БД — как в текущей логике). Не открывать админские разделы «на всякий случай».

**Контент обработки:**

1. Заголовок `Отель «…»`, подзаголовок из текущей логики (корпуса / без корпусов).
2. Карточка «1 · Исходные файлы»:
   - зона «Данные — брони»;
   - зона «Номера — расселение»;
   - кнопки «Колонки «Данные»», «Колонки «Номера»» — те же обработчики, что сейчас.
3. Карточка «2 · Обработка»:
   - квартал — **только если согласован пункт A**;
   - дубли — **только если согласован пункт B**;
   - фиолетовая плашка про переход квартала — можно сразу (это подсказка, не логика);
   - кнопка «Обработать и сохранить» = текущий пайплайн + `filedialog.asksaveasfilename` как сейчас.
4. Карточки статистики — **только если согласован пункт C**.

**Зона файла, состояния:**

| Состояние | Вид | Действие |
|---|---|---|
| Пусто | светлый фон `#F7FAFC`, рамка `#C5D2E0`, текст-подсказка, «Обзор…» | клик по зоне или кнопке → `filedialog.askopenfilename` |
| Выбран | фон `#E5F7EE`, рамка `#B7E0C8`, **имя файла** (не полный путь; путь в tooltip), «Заменить» | то же |
| Ошибка чтения | фон `#FDECEC` | `messagebox.showerror` как сейчас |

Пунктир необязателен: сплошная рамка 1–2 px ок. Настоящий drag-and-drop не нужен в первой итерации.

Крестик «сбросить файл» — желателен, в макете его нет: добавьте мелко справа от имени.

**Статусбар** оставить. Тексты вроде «Готово к работе», «Обработка…». Справа — путь к БД (как подсказка, не редактор).

Во время обработки: CTA disabled, статус «Обработка…», курсор `watch`. После успеха — `messagebox` или тост + запись в историю. После ошибки — `messagebox.showerror`, кнопка снова активна.

### 6.2. История

Тот же сайдбар. Сверху кнопки как сейчас: Обновить, Открыть оригинал, Открыть результат, Удалить.

Treeview колонки **не переименовывать и не выкидывать** — те же, что в 2.6: №, Отель, Квартал, Обработан, Строк, Дубли, Оригинал, Результат.

Стиль Treeview — `clam`, см. раздел 8. Отель можно красить тегом (`tag_configure`), дубли > 0 — янтарный текст, 0 — зелёный. Не обязательно pill-вид, ttk это плохо умеет.

Низ: «Брони с переходом кварталов в выбранном отчёте».

- нет выбора / нет строк → одна фраза серым, не пустой холст;
- есть строки → текущая таблица/список, без смены модели данных.

Поиск (пункт I) — после основной вёрстки или никогда.

Удаление — по-прежнему через `messagebox.askyesno`.

### 6.3. Настройки (`CTkToplevel`)

Отдельное окно, как сейчас, не вкладка главного. Модальность — как сейчас (`transient` + `grab_set`, если уже есть).

Вместо `CTkTabview`:

```
[ заголовок + крестик ]
[ левое меню 196px | контент скролл ]
[ Сохранить ] [ Отмена ]
```

Меню:

```
ОТЕЛИ
  Чайковский
  Дона
  Усадьба
СПРАВОЧНИКИ
  Агенты
  Пользователи
СИСТЕМА
  База данных
```

Пользователь отеля этот экран либо не видит, либо видит только свой отель — **как в текущем коде**.

Футер Сохранить / Отмена **не скроллится**. Сохранить пишет все изменённые разделы (отели + агенты + пользователи + путь БД), как сейчас, если сейчас один общий Save. Если сейчас вкладки пишутся по-разному — не объединять наугад.

**Вкладка отеля** (три отеля — один и тот же layout, разные значения):

- Ставка %, минимум ₽, порог — те же три числа.
- Три чекбокса с **теми же формулировками**, что в 2.6 (не сокращать смысл):
  - Налог включён в стоимость (делитель 100+ставка)
  - Порог — автоматически: минимум×(100+ставка)/ставка
  - Считать налог от стоимости БЕЗ комиссии (100%)
- Блок «Шаблоны Excel-формул» **свёрнут**. Кнопка «Показать формулы» / «Сбросить по умолчанию» внутри, логика прежняя.

При включённом автопороге поле порога disabled — если так уже сделано; если нет, не придумывать, пока не попросите.

**Агенты:** master–detail сохранить.

- Слева список (CTkScrollableFrame), справа форма.
- Кнопки: Добавить, Удалить, Импорт, Экспорт, Проверить — все оставить, это не декорация.
- Поля: Название, Применяется к, Синонимы, периоды (с / по / %).
- «Пустые даты = базовая ставка» — текст оставить.
- Импорт/экспорт/проверка — текущие диалоги, только кнопки в новой палитре.

**Пользователи:** Treeview Логин / Роль / Отель + Добавить / Сменить пароль / Удалить. Диалоги пароля — текущие `CTkToplevel`/`CTkEntry`, покрасить.

**База данных:** путь, поясняющий текст (можно слово в слово со скрина), «Сменить папку…», «Сбросить (рядом с приложением)». Поведение не менять: применилось — работает без рестарта.

### 6.4. Диалоги, которых нет в HTML

Их **нужно** привести к палитре, не выкидывать:

1. **Вход** — логин/пароль. Карточка по центру, кнопка входа зелёная или синяя, ошибка через `messagebox`.
2. **Сопоставление колонок** — поля взять из кода, не из HTML. Две колонки: название поля | выбор колонки файла (`CTkOptionMenu` или Entry — как сейчас).
3. **Нераспознанные источники** — список агентов, которых нет в справочнике. Обычно «добавить синоним / пропустить / указать агента». Повторить текущий сценарий в новых рамках.

Размер диалогов: не на весь экран. Колонки ~560–640 px, нераспознанные — по числу строк, скролл.

## 7. Тексты — не «улучшать»

Копирайт бухгалтерии уже притёрт. Менять формулировки нельзя, кроме явных опечаток.

Оставить как есть:

- «Данные» / «Номера»
- «Колонки «Данные»», «Колонки «Номера»»
- «Обработать и сохранить» (в макете sentence case — **можно** «ОБРАБОТАТЬ И СОХРАНИТЬ», если так привыкли)
- «переход кварталов — фиолетовым»
- плейсхолдеры формул
- «Пустые даты = базовая ставка»
- «Пользователь отеля видит только свой отель и его историю»
- «Смена пути применяется сразу, перезапуск не нужен»

Новые тексты, которые можно взять из макета:

- подсказка пустой зоны «Данные»: «Выгрузка броней: даты, сумма, источник, гости»
- пустая история перехода: «Выберите отчёт в таблице — здесь появятся строки, пересекающие границу квартала»

## 8. Соответствие виджетов

| Макет | Делать так |

| Сайдбар, карточки, зоны файлов, плашки | `CTkFrame` + `CTkLabel` |

| Ставка, год, синонимы, формулы | `CTkEntry` |
| Чекбоксы | `CTkCheckBox` |
| Квартал I–IV | `CTkSegmentedButton` (есть в customtkinter) **или** 4 `CTkButton` |
| Левое меню настроек | столбец `CTkButton`, не Tabview |
| Скролл настроек / агентов | `CTkScrollableFrame` |
| История, пользователи | `ttk.Treeview` |
| Выбор колонки файла | как сейчас: `CTkOptionMenu` / Combobox |
| Файлы | `filedialog` |
| Ошибки, «удалить?», «сохранить как» | `messagebox` + filedialog |
| Тост | не обязателен; если делать — маленький `CTkToplevel` overrideredirect, 2.5 с, правый нижний угол |

Treeview:

```python
style = ttk.Style()
style.theme_use("clam")
style.configure(
    "Treeview",
    background="#FFFFFF",
    fieldbackground="#FFFFFF",
    foreground="#1A2332",
    rowheight=32,
    font=("Segoe UI", 10),
    borderwidth=0,
)
style.configure(
    "Treeview.Heading",
    background="#F7F9FC",
    foreground="#5C6B80",
    font=("Segoe UI", 9, "bold"),
    relief="flat",
)
style.map(
    "Treeview",
    background=[("selected", "#EAF1FF")],
    foreground=[("selected", "#1A2332")],
)
```

На Windows `clam` иногда странно рисует заголовки — если поедет, откатиться на default и поменять только `rowheight` + теги строк. Не блокировать редизайн из‑за Treeview.

Иконки: папка `assets/` PNG 16×16 через `CTkImage` (Pillow уже, скорее всего, тянется). Если лень — кнопки без иконок, только текст. Не подключать Font Awesome.

## 9. Сетка и pack/grid (чтобы не разъехалось)

Главное:

```
root
  sidebar   pack left, fill=y, фиксированная ширина
  right     pack fill=both, expand
    content  pack fill=both, expand  (CTkScrollableFrame)
    status   pack fill=x, bottom
```

Шаги 1 и 2:

```
inner.grid
  step1  column 0, weight=3
  step2  column 1, weight=2
  pady/padx = 8–10
```

При ширине контента < ~720: `grid_forget` и pack вертикально. Не обязательно слушать каждый resize — можно проверить на 1280×800 и 1100×700.

Настройки:

```
top     pack fill=x
body    pack fill=both, expand
  nav   pack left, fill=y, width=196
  pane  pack fill=both, expand  (Scrollable)
foot    pack fill=x
```

Не класть CTA «Обработать» внутрь Scrollable так, чтобы она уезжала — на 700 px высоты оба шага должны быть видны без скролла на Чайковском. Статистика может уезжать вниз.

## 10. Порядок работ (чтобы не сломать расчёт)

Делать **веткой**, каждый шаг — запускаемый exe/скрипт.

**Шаг 1. Тема.** Словарь цветов, фон окна, сайдбар navy, шрифты. Поведение 1:1. Приёмка: все кнопки работают как в 2.6.

**Шаг 2. Карточки шагов.** Серые панели → белые карточки. Entry файлов пока оставить.

**Шаг 3. Зоны файлов.** Тот же `StringVar` пути, другой виджет. Кнопка «Колонки» без изменений.

**Шаг 4. Настройки.** Tabview → левое меню. Формулы свернуть. Поля и Save как были.

**Шаг 5. Treeview + пустые состояния.** История и пользователи.

**Шаг 6. Диалоги.** Логин, колонки, нераспознанные источники — палитра.

**Шаг 7 (только после ответов на A–N).** Квартал на форме, чекбокс дублей, статистика, поиск, тост.

Не начинать с шага 7. Не рефакторить pandas «заодно». Не переименовывать таблицы sqlite.

Регрессия на каждом шаге:

- обработка Чайковского с двумя файлами;
- Дона и Усадьба;
- дубли и фиолетовые строки в xlsx;
- агент с периодом комиссии;
- пользователь отеля не видит чужое;
- смена пути БД без рестарта;
- PyInstaller: один прогон перед сдачей.

## 11. Критерии приёмки (для заказчика)

Редизайн принят, если:

1. Бухгалтер узнаёт все те же действия, что в 2.6, без обучения дольше 5 минут.
2. На главном видно: какой отель, выбран ли файл, чем закончилась прошлая обработка (хотя бы датой в истории).
3. «Обработать и сохранить» даёт **байт-в-байт тот же смысл** результата (те же листы, те же формулы, фиолетовый переход). Сравнивать xlsx до/после на одном комплекте выгрузок.
4. Настройки по-прежнему пер-отель, применяются только к **новым** обработкам.
5. Админ / отель — права не разъехались.
6. Сборка PyInstaller открывается на чистой Windows без Python.
7. Светлая тема, читаемые подписи, нет обрезанного текста при 125% DPI (проверить).

Не критерии: «как на сайте», анимации, тёмная тема, pixel-perfect с HTML.

## 12. Ограничения customtkinter — не биться

| Хочется как в HTML | Реально |
|---|---|
| Пунктирная drop-zone | Сплошная рамка или один `Canvas` |
| Drag-and-drop Excel | Не делать в v1 |
| Pill в Treeview | Теги цвета текста/фона строки |
| Тени карточек | Бордер + контрастный фон |
| Кастомный titlebar | Системный |
| Плавный overlay настроек | Обычный `CTkToplevel` |
| SVG | PNG через CTkImage |
| Две колонки, которые сами складываются | Ручной grid / pack по ширине |

Scaling: `customtkinter.set_widget_scaling` / `set_window_scaling` не крутить без нужды. Проверить 100% и 125% DPI.
