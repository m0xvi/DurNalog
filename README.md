# DurNalog (TurNalog) — v3.12

Интерфейс — дизайнерский пакет `TurNalog_ui/` (customtkinter),
боевая логика — `core.py`/`db.py`/`agents.py`/`tax.py`, связка — `main.py`
(хуки `hook_*`: обработка, история, настройки, пользователи, БД, авторизация).

Редизайн по макету дизайнера (`ui_theme.py` — палитра/шрифты):
тёмно-синий сайдбар с цветными точками отелей, белые карточки шагов,
зоны файлов вместо текстовых полей, квартал и чекбокс дублей на форме,
настройки с левым меню и свёрнутыми формулами, стильные таблицы и тосты.
Поведение расчёта, БД и прав — без изменений.

Десктоп-приложение (Windows) для расчёта туристического налога по выгрузкам
из отельных систем. Python + customtkinter, сборка в EXE через PyInstaller.

## Интерфейс

Тема — фиксированно **светлая**. При запуске — **окно входа**: пользователи
хранятся в локальной БД (пароли — в виде хешей). При первом запуске создаётся
`admin / admin` — смените пароль.

**Расположение БД** выбирается при первом запуске («рядом с приложением» или
общая/сетевая папка) и меняется в «⚙ Настройки → Данные» (при желании — с
копированием текущей базы). Общая папка = общие история, дубли и пользователи
для нескольких компьютеров; смена пути применяется без перезапуска.

Роли:
- **администратор** — все отели, История, «⚙ Настройки» (в т.ч. вкладки
  «Агенты» и «Пользователи»: добавить/удалить, сменить пароль; последнего
  админа удалить нельзя);
- **пользователь отеля** — видит только свой отель и историю по нему.

Боковая навигация: **Чайковский · Дона · Усадьба · История · ⚙ Настройки**
(по правам). Каждый отель — «карточки-шаги»: 1) исходные файлы →
2) обработка. Диалоги автоматически подстраивают высоту под содержимое.
Обработка идёт в фоновом потоке, результат — в статус-баре и сводке;
журнал — `turnalog.log`.

### Настройки (⚙)

По каждому отелю отдельно настраиваются:
- ставка налога, %; минимум за ночь, ₽;
- «налог включён в цену» (делитель 100+ставка) или начисление сверху (/100);
- **«считать налог от стоимости с комиссией (100%)»** — включён по
  умолчанию: цена в файле — это нетто (без комиссии агента), база каждой
  строки восстанавливается до 100% (Стоимость/(100−K)×100), налог считается
  от неё. Выключайте, только если в файле уже полные цены гостя;
- порог метода «ставка» — вручную или автоматически (мин×(100+ставка)/ставка);
- **шаблоны Excel-формул** (Сут.ставка / Метод / Налог) с плейсхолдерами
  `{P} {N} {R} {M} {T} {min} {rate} {div}`, кнопками «Показать формулы» и
  «Сбросить по умолчанию».

Там же — общая вкладка **«Агенты»** (список слева, карточка справа):
- ➕ добавлять / ✕ удалять своих агентов;
- **«Применяется к»** — галочки отелей (Чайковский/Дона/Усадьба);
- **синонимы** названий в отчётах (через запятую);
- **плавающая комиссия по периодам**: строки «с … по … %», пустые даты =
  базовая ставка; для брони берётся период, содержащий дату заезда;
- **Импорт/Экспорт** таблицы агентов (Excel/CSV: Название | Отели |
  Синонимы | С даты | По дату | Комиссия %) — для бэкапа и переноса на
  другой компьютер; несколько строк с одним названием = периоды;
- «Проверить» — тест распознавания источника.

Распознавание устойчиво к вариантам написания: точное совпадение →
подстрока → транслитерация («Островок» = «Ostrovok») → похожесть ≥ 0.85
для сокращений и опечаток. Нераспознанные источники при запуске Доны
попадают в диалог: сопоставить с агентом / создать нового / 0%.
Всё хранится в `turnalog_config.json` и применяется к новым обработкам.

Там же — вкладка **«Обновления»** (только чтение настроек не требует):
- текущая версия и кнопка **«Проверить сейчас»** — запрос к GitHub Releases;
- **«Скачать и установить»** с прогрессом — ставится поверх EXE-версии,
  данные (настройки, история, БД) сохраняются, приложение перезапускается;
- список изменений найденной версии и кнопка «Страница релиза»;
- галочки **«Проверять при запуске»** (тихо, с уведомлением при находке)
  и «Скачивать автоматически». Ручная установка доступна только в собранной
  EXE-версии; при запуске из исходников кнопки установки отключены.

### Сопоставление колонок

После выбора файла приложение читает его заголовки. Если сохранённого
сопоставления нет (или колонки не совпадают), открывается диалог
«Сопоставление колонок»: для каждого поля приложения (Гость, Стоимость,
Заезд…) выбирается колонка файла — с кнопкой **Автоподбор** по синонимам
(«Сумма»/«Цена»/«Стоимость», «Прибытие»/«Заезд» и т.д.). Обязательные поля
помечены «*». Галочками внизу отмечается, какие **дополнительные колонки
файла перенести в результат**; все неотмеченные игнорируются. Сопоставление
запоминается в `turnalog_config.json` и переиспользуется для следующих файлов;
кнопка «⚙ Настроить колонки…» открывает диалог вручную.

## Отели

- **Чайковский** — «Данные» + «Номера» → листы `1&2`, `нет корпуса`, `1`, `2`
  с формулами налога и подсветкой пропусков.
Все три отеля считают комиссию агентов одинаково: по колонке «Источник»
(Усадьба — по «Организация-заказчик») распознаётся агент из встроенной
таблицы своего отеля (Дона — 57 агентов + прямые каналы; Чайковский и
Усадьба — свои таблицы из файлов отеля, включая плавающие проценты по датам,
например Яндекс 15%→18% с 01.02.2026 или OTELLO 15→17→20%). В результат
добавляются «Комиссия %», «Агент» и «Стоимость без комиссии»
(=Стоимость/(100−K)*100 — восстановление 100% цены из нетто); налог и формулы
считаются от неё. Цена в файле при этом подписывается «без комиссии». Если встречаются неизвестные
источники, при запуске открывается диалог: сопоставить с существующим
агентом, **создать нового агента глобально** (имя + % + синоним) или оставить
0%; выбор сохраняется и больше не спрашивается.
- **Усадьба** — отчёт UCS Shelter «Доход по номеру» (структура фиксированная,
  сопоставление не нужно).

Битые Excel-выгрузки (невалидный XML в стилях — PMS любят такое) чинятся
автоматически в 5 уровней: короткий rgb → чистка styles.xml → чистка всех
xml → пересборка стилей с сохранением форматов дат → минимальные стили.
Первые три без потерь и молча; последние два показывают предупреждение
в финальном диалоге («…открыт после восстановления…» / «СИЛЬНО повреждён…»).
Совсем нечитаемый файл даёт понятную ошибку с советом пересохранить его
в Excel (Файл → Сохранить как → .xlsx).

## История и переход кварталов (вкладка «История»)

При обработке выбирается квартал отчёта; в `turnalog_history.db` (SQLite,
рядом с EXE) сохраняются копии исходного и итогового файлов и распознанные
брони. Гость, попавший в два квартальных отчёта (то же ФИО + пересечение дат
или тот же № брони), во втором отчёте помечается **фиолетовым** с примечанием,
куда он уже попал; налог не пересчитывается (пометка для бухгалтера).
В истории — список отчётов, открытие оригинала/результата, удаление,
просмотр дублей.

## Расчёт налога (общий, `tax.py`)

```
Сут.ставка = Стоимость / Ночей
Метод      = ЕСЛИ(Сут.ставка >= 5100; "ставка"; "мин.ставка")
Налог      = ОКРУГЛ(ЕСЛИ(Метод="мин.ставка"; Ночей*100; Стоимость/102*2); 2)
```

Значения по умолчанию: ставка 2% (2026 г., включена в цену), минимум
100 ₽/сутки, порог 5100. Все параметры и формулы меняются в окне
«⚙ Настройки» по каждому отелю; дефолты — `DEFAULT_TAX` в `tax.py`.

## Подсветки в итоговых файлах

красный — нет № комнаты (Чайковский) · жёлтый — нет гостя / неизвестный
агент · оранжевый — нет дат · голубой — нет стоимости · фиолетовый —
переход кварталов · зелёный — итоги.

## Структура кода

- `main.py` — GUI (редизайн v2.1), обработка, диалог сопоставления колонок
- `schemas.py` — поля входных файлов + синонимы для автоподбора
- `agents.py` — таблица агентов Доны и нечёткое сопоставление источников
- `tax.py` — константы/формулы налога, разбор цен и дат
- `db.py` — SQLite-история отчётов и поиск дублей
- `tests/` — pytest (`python -m pytest tests -q`)

## Запуск и сборка

```
build.bat        # Windows: venv + зависимости + PyInstaller → dist\TurNalog\TurNalog.exe
```

Или без сборки: `pip install -r requirements.txt && python main.py`.

## Релизы (EXE в GitHub Releases, исходники в main)

В репозитории только исходники (`build/`, `dist/`, БД и логи — в .gitignore).
EXE раздаётся через Releases двумя способами:

**Авто:** на каждый тег `v*` GitHub Actions (`.github/workflows/build-exe.yml`)
сам собирает EXE на windows-latest и публикует релиз с архивом
`TurNalog-win64.zip`:

```
git tag v2.3
git push origin v2.3
```

**Вручную:** `build.bat`, затем `make_release.bat` — упакует dist в
`TurNalog-win64.zip`; на GitHub: Releases → Draft new release → tag `v2.3` →
прикрепить zip → Publish.
